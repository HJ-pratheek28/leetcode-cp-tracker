# LeetCode & Competitive Programming Tracker

A personal, pattern-first tracker for LeetCode and competitive programming. Use it to record problems, recognize the underlying technique, and revisit mistakes—not just count solved questions.

## How to use

1. Pick one pattern from `problems/`.
2. Solve a problem before looking at editorial hints.
3. Add it to that pattern's table with the link, difficulty, status, and a short note about the key idea.
4. If you needed a hint or made a mistake, revisit it after 1 day, 1 week, and 1 month.
5. Track your reasoning and complexity; avoid copying full solutions into the notes.

- ✅ Solved independently

## Problem log template

Copy this row into the relevant pattern file:

`| [Problem name](URL) | Easy/Medium/Hard | ⬜ | Key observation, approach, complexity, and what to revisit | YYYY-MM-DD | YYYY-MM-DD | YYYY-MM-DD |`

Suggested columns: **Problem**, **Difficulty**, **Status**, **Short note**, **Review 1 (+1 day)**, **Review 2 (+7 days)**, **Review 3 (+30 days)**.

## Weekly review

- [ ] Re-solve problems marked 🟡 without notes.
- [ ] Explain the pattern in plain language.
- [ ] Record why the first approach failed.
- [ ] Solve one new problem that combines two patterns.
- [ ] Update the tracker honestly.

## Guidelines

- A problem is not truly mastered just because the code passed once.
- Write the trigger for the pattern (e.g. *sorted input + pair condition*), not only the algorithm name.
- Include time and space complexity in your own notes.
- Use C++ or Python—focus on the reasoning, not language switching.
