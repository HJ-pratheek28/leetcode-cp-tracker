# Algorithm Roadmap

Advance when you can solve representative unseen problems and explain correctness—not merely after finishing a playlist.

## Stage 1 — Foundations
- [ ] Big-O, auxiliary space, amortized analysis
- [ ] Arrays, strings, sorting, hashing
- [ ] Prefix sums and difference arrays
- [ ] Two pointers and sliding windows
- [ ] Binary search and search on answer
- [ ] Recursion and iterative simulation

**Exit check:** derive brute force, identify the bottleneck, justify the optimization.

## Stage 2 — Core data structures
- [ ] Linked lists and fast/slow pointers
- [ ] Stacks, queues, deques
- [ ] Monotonic stack and queue
- [ ] Heaps / priority queues and top-K
- [ ] Intervals and sweep line
- [ ] Tree DFS/BFS and iterative traversals
- [ ] BST properties and operations

**Exit check:** choose structures based on required operations and their costs.

## Stage 3 — Graphs
- [ ] Adjacency lists / matrices
- [ ] DFS, BFS, grid traversal, components
- [ ] Cycle detection and bipartite graphs
- [ ] Topological sorting and DAG DP
- [ ] Union-Find / DSU
- [ ] Dijkstra (non-negative weights)
- [ ] Bellman–Ford
- [ ] Kruskal and Prim
- [ ] Strongly connected components
- [ ] Bridges and articulation points

**Exit check:** select methods using graph direction, edge weights, and query type.

## Stage 4 — DP and greedy
- [ ] State, transition, base case, answer extraction
- [ ] 1D and grid DP
- [ ] Knapsack and subset sum
- [ ] LIS, LCS, edit distance
- [ ] Interval DP and tree DP
- [ ] Bitmask DP
- [ ] Greedy proofs: exchange argument and invariants
- [ ] Binary search + greedy feasibility

**Exit check:** define a sufficient state and justify why the recurrence covers all choices.

## Stage 5 — Advanced techniques
- [ ] Fenwick tree / BIT
- [ ] Segment tree and lazy propagation
- [ ] Sparse table and range-query trade-offs
- [ ] Trie, KMP, Z-function, rolling hash
- [ ] Coordinate compression and offline queries
- [ ] LCA, binary lifting, Euler tour
- [ ] Meet-in-the-middle and digit DP
- [ ] Network flow / matching
- [ ] Computational geometry
- [ ] Amortized analysis in data structures

**Exit check:** explain supported operations, complexity, limitations, and why a simpler tool is insufficient.

## Stage 6 — Contest execution
- [ ] Rank problems by confidence
- [ ] Derive complexity from constraints
- [ ] Write adversarial tests
- [ ] Practice timed debugging
- [ ] Upsolve missed problems after contests
- [ ] Re-solve upsolved problems a week later
- [ ] Classify mistakes: modeling, algorithm, proof, implementation, overflow, edge case

## Suggested weekly cadence
- 3 focused pattern sessions
- 1 spaced-review session
- 1 mixed-pattern session
- 1 contest or timed set with postmortem
- 1 lighter planning / notes session

Adjust volume around college. Consistent review beats unrealistic targets.
